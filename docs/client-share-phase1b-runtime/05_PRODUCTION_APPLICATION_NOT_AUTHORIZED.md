# Production Application — Not Authorized

Read this even if every test in this package passed.

## What passing these tests proves

A `PHASE_1B_RUNTIME_PASS` result from `03_RUN_PHASE1B_RUNTIME_TESTS.sql`
confirms that, against a clean disposable PostgreSQL database with the
seven migrations applied exactly as committed:

- `202608030003_client_share_owner_foundation.sql`
- `202608030004_client_share_session_foundation.sql`
- `202608030005_client_share_integrity_and_security.sql`
- `202608050001_client_share_owner_reads.sql`
- `202608060001_client_share_lifecycle_operations.sql`
- `202608060002_client_share_access_operations.sql`
- `202608060003_client_share_configuration_save.sql`

every one of the fourteen Phase 1B owner-facing RPCs behaves as designed
for an authenticated owner (and, where applicable, a second authenticated
owner and an unauthenticated caller) against the exact tables, triggers,
grants and RLS policies those migrations create — including the
one-active-link-per-project rule, PIN/expiry/rotation/revoke behavior, the
atomic configuration-save operation (settings, tasks, Resources, update
publication) with real rollback on partial failure, the
configuration-version staleness contract, and tenant isolation.

## What passing these tests does NOT prove or authorize

- The disposable test fixture (`01_CREATE_TEMP_TEST_FIXTURE.sql`) is a
  deliberately minimal stand-in for `public.projects`, `public.tasks`,
  `public.clients`, `public.task_resources`, `public.project_updates` and
  `public.project_timeline_events` — only the columns the Client Share
  migrations actually reference. It does not, and is not intended to,
  match the real production schema in every column, constraint, trigger
  or default the production tables actually carry.
- Passing this package does **not** authorize applying any of the seven
  migrations above to the real Text2Task production project.
- It does not replace a review of the actual production schema for these
  same tables, nor any prior blocking decision documented elsewhere for
  this feature.
- It does not authorize proceeding to Phase 2 (public `/share/**` routes,
  anonymous session/grant issuance, the public projection) — Phase 2 is a
  separate, later scope this package does not touch at all.
- A successfully *generated* package (file `02` mechanically assembled,
  `build-phase1b-runtime-package.test.ts` passing) is not by itself
  runtime proof of anything — only an actual run of file `03`, captured in
  `04_CAPTURE_RESULTS.md`, is.

## Hard rules

- The Production Text2Task project must never receive file `01` or file
  `03` from this package.
- Only the seven original, committed migration files under
  `supabase/migrations/` are ever candidates for Production application —
  and only exactly as written, never as edited copies, and never as the
  generated bundle in file `02` (which exists solely for temporary-project
  SQL Editor convenience).
- Production application of these migrations requires a separate,
  explicit, later decision by the project owner. This package makes no
  such decision and grants no such authorization.
- No production bundle and no production-application script was
  generated by this package or by the agent that produced it.
